四个小型 Agent 项目

每个项目都保留了“为什么做、怎么搭、如何控制风险、如何测试”的痕迹。它们规模不大，但覆盖了 AI 应用岗位常见的真实工作颗粒度。

Project 00 · RAG + Ollama

校规问答系统

基于本地校规文本构建检索问答，支持语义检索、关键词补强、本地规则引擎和 Ollama 裁判，前端用 Streamlit 呈现可调试问答界面。

RAG Ollama DeepSeek Streamlit 本地规则引擎
  • 场景学生询问校规是否允许某行为，系统需要给出判定、原因和规则来源。
  • 设计使用 BAAI/bge-small-zh 做语义检索，叠加关键词分数，Top-K 召回后交给规则引擎或本地模型判定。
  • 价值证明能理解 RAG 的检索、排序、上下文裁剪、可解释来源和调试模式。
Project 01 · Coze Customer Agent

企业知识库客服智能体

模拟智能硬件电商 NovaTech，搭建面向售前咨询、售后政策、物流发票、投诉处理和工单摘要的 Coze 客服智能体。

Coze 知识库问答 客服流程 工单摘要 边界控制
  • 场景客户咨询产品、退换货、保修、物流异常时，Agent 需要专业回复并识别转人工条件。
  • 设计整理 5 份企业知识库资料，围绕客服身份、知识库优先、高风险承诺限制设计系统提示词。
  • 价值证明能用 Coze 完成知识库配置、角色设定、演示案例、边界测试和结构化输出。
Project 02 · Job Matching Agent

AI 求职岗位匹配助手

面向 AI 应用方向求职者，输入岗位 JD 后输出岗位类型判断、人岗匹配评分、投递建议、简历优化和面试问题。

Coze JD 分析 评分机制 简历优化 面试准备
  • 场景AI 岗位名称复杂，求职者需要判断岗位是否真实匹配 AI 应用落地方向。
  • 设计设置岗位方向、项目经验、技能要求、门槛可达性、投递性价比 5 个评分维度。
  • 价值证明能把模糊求职问题产品化，设计可解释的决策逻辑和真实性边界。
Project 03 · Python + FastAPI + Dify

门店评论分析与自动回复 Agent｜Python + FastAPI + Dify

基于 Python / Pandas 构建门店评论分析流程，实现 CSV 读取、评分统计、差评筛选和问题分类；使用 FastAPI 将分析逻辑封装为公网 API，并通过 Dify HTTP 请求节点调用 API，由 LLM 自动生成门店经营分析周报和典型差评回复建议。

Python Pandas FastAPI Uvicorn Render Dify Prompt Markdown CSV
  • 数据使用 Python / Pandas 对门店评论 CSV 进行评分统计、差评筛选和问题分类。
  • API使用 FastAPI 封装评论分析接口，支持 JSON 请求与 CSV 文件上传。
  • 部署将 API 部署至 Render 公网环境，并提供 Swagger 接口文档。
  • 闭环在 Dify 中通过 HTTP 请求节点调用公网 API，实现“数据处理 → API 调用 → LLM 周报生成”的自动化闭环。
GitHub Render API Swagger 文档 V2 演示视频

V1 版本：早期使用 Python / Pandas 生成结构化 Markdown，再复制到 Coze 生成经营周报和回复建议；当前主线已升级为 FastAPI 公网 API + Dify 工作流。

Workflow

我的 Agent 搭建方法

这是一套适合 AI 应用实施和产品助理岗位的工作方法：先定义场景，再设计 Agent 能力，最后用测试把边界打磨出来。

Step 01

把业务问题改写成任务

明确用户输入是什么、Agent 应该输出什么、哪些内容必须转人工或提示风险。

Step 02

准备知识库和结构化数据

把规则、FAQ、产品资料、岗位信息或评论数据整理成可检索、可引用、可复用的材料。

Step 03

设计角色、流程和输出模板

在 Prompt 中写清身份、任务、判断规则、回答格式和禁止事项，让 Agent 输出更稳定。

Step 04

用演示案例和边界问题测试

不只测试正常问题，也测试退款、投诉、虚构信息、岗位伪装、差评安抚等高风险输入。
